> All source observations and compiler adapters target v2 `.nir` only.

## Motivation

The graph can expose missing declarations and inconsistent bindings,
but stronger claims need analysis with explicit coverage and evidence.
Agents and the UI need durable, addressable findings without confusing
LLM suggestions, structural checks and proofs.

## Non-goals

No replacement Rust typechecker, universal dead-code detector, inference
of every unstated business requirement, or proof from graph adjacency
alone. Runtime approval enforcement belongs to [RFC 0021.b](0021.b-approval-runtime.md).

## Design

### Findings and their authority

Add service-generated `AnalysisFinding` nodes with rule ID, target IDs,
exact input revisions, supporting path/counterexample, checker identity,
coverage limits, and classification: `proven_violation`,
`proven_satisfied`, `potential_issue`, or `unknown`. LLM suggestions
remain proposals; they cannot write authoritative checker findings.

Deterministic structural checks include undefined roles/states/events,
missing referenced hooks, invalid bindings, missing initial states,
illegal terminal transitions, conflicting literal constraints, absent
required approval policies and structurally unreachable states. Role
slot feasibility also needs the runtime identity/assignment population;
a valid policy can still be unfulfillable for today's available people.

Guard satisfiability, implied preconditions at calls, contradictory
policies and infeasible transitions require the appropriate supported
expression/control-flow analysis or solver. Report unsupported cases
as unknown. A path's presence in the state graph does not prove its
guards can ever be satisfied, and reaching a cycle does not by itself
prove either deadlock or eventual completion.

Whole-program reachability treats workflow entry/exit hooks, event
handlers, routes, application entry points and exported callbacks as
roots or explicit call paths. A function absent from `main`'s call tree
can still be reachable through a workflow. Indirect/unresolved calls
make negative reachability conclusions conditional; label apparent
dead code accordingly. Statement-level dead code needs body control
flow, not only function-to-function edges.

Missing business obligations can be flagged against declared domain
rules, templates or requirements coverage. The graph cannot prove that
an unstated business requirement does not exist. Required role policies
flow along typed calls and authorization context; an internal helper
does not automatically need a second externally exposed access gate.

### Stored finding schema

Register a versioned `AnalysisFinding` TypedSpec with:

```text
id, rule_id, rule_version
classification: proven_violation | proven_satisfied | potential_issue | unknown
target_ids[], input_snapshot_id
input_entities[{id, spec_revision, spec_hash}]
source_blob_hashes[], dependency_hash
checker_id, checker_version, configuration_hash, toolchain_id?
coverage: modeled_constructs[], omitted_constructs[], assumptions[]
evidence_artifact_ids[], witness_or_counterexample?
message, suggested_gap_ids[]
supersedes_finding_id?
```

Use core hash recipes and schema-version retention. The checker adapter
creates findings through a service-only evidence operation; an agent
may request analysis or propose an issue but cannot choose its own
authoritative `classification` or impersonate a checker. "Proven" is
always relative to the declared rule/model/assumptions, not a statement
that an entire application is safe. A compiler build success alone
cannot produce `proven_satisfied` for an unchecked business requirement.

### Checker execution and freshness

The host installs an allowlisted adapter registry with supported rules,
input schemas, trust/coverage declarations and bounded execution limits.
Agents choose rule IDs, not shell commands or arbitrary checker URLs.
An optional `graph_analyze` tool creates a bounded analysis job over an
immutable snapshot; `graph_analysis_status(job_id)` retrieves progress
and result IDs. These extension tools are separate from core
`graph_validate`, which does not claim semantic analysis.

Run checkers outside graph transactions. Persist result artifacts first,
then record findings against the exact snapshot and versions analyzed.
If input changed during execution, retain historical findings but mark
their current applicability stale. Never attach an old result as evidence
for a new node/body revision. Cancellation/timeouts produce a job outcome
and `unknown` for incomplete requested checks, not a clean result.

Freshness is separate from classification: `current`, `stale`, or
`unknown`. Changing a dependent spec, body, toolchain, checker version,
configuration or required runtime assumption invalidates applicability.
While the dependency invalidation walk is incomplete, freshness is
unknown. Record run manifests even for no-findings results, so absence
of issues can be distinguished from a check that never ran.

Findings/evidence are immutable; a subsequent run supersedes the prior
finding with a linked new record. A UI dismissal does not change a
checker result or satisfy a mandatory check. Optional issue dismissal
is a separate audited Decision node. When a checker owns a blocking gap,
its adapter can resolve/reopen that gap under the core lifecycle based
on exact finding revisions. An agent cannot resolve a checker-owned gap
by asserting that a repair worked.

### Required rule families and honest boundaries

| Rule family | Input | Claim boundary |
|---|---|---|
| Declaration/reference integrity | Typed specs and Role/Claim references | Definite structural errors; core validators can supply these findings without a solver |
| Call/policy obligations | Bound arguments, preconditions, authorization context, effects | Establish or refute obligations only for modeled expressions and call paths |
| Workflow reachability | 0021.a initial states, transition topology and guards | Topological reachability separate from feasible guarded execution |
| Function reachability | Explicit entry points, exports, routes, workflow hooks, calls | Negative claims require coverage of all relevant roots/indirect calls |
| Statement reachability | Parsed body control-flow/value model or compiler evidence | Not derivable from a declaration-only graph |
| Requirement coverage | Declared obligations and implementation/check links | Missing links or missing demanded checks, not discovery of all unstated obligations |

Positive path witnesses can show a modeled route exists. An unresolved
callback or external entry point prevents a definitive whole-program
dead-code conclusion; report the limited scope or `unknown`. Predicate
solver failures/unsupported expressions are not evidence of either
satisfiability or contradiction. Static approval checks do not establish
that deployed identities satisfy 0021.b's person-equivalence contract.

## Effect on the permission model

Reading findings uses core project read grants. Running a checker needs
a host-authorized bounded analysis grant and adapter; it does not grant
arbitrary execution. Only authenticated adapters record authoritative
findings/evidence. Existing compiler/runtime authorization boundaries
remain in force. Inspecting private runtime evidence requires separate
authorization; a project agent has no automatic production access.

## Compatibility

An optional typed schema/tool extension, independent of core A–E.
Core source-divergence reconciliation remains an addressable Gap and
does not require AnalysisFinding support. Existing v2 compiler checks
retain their actual scope; no new proof or source-dialect support is
inferred from importing an existing verdict.

## Acceptance criteria

| Stage | Deliverable | Evidence |
|---|---|---|
| C1 | Finding schema, evidence links and protected write path | Read/query/export exact findings; reject agent-forged checker identity/classification; retained history |
| C2 | Structural rule adapters | Undefined role, missing hook, bad binding and incompatible literal constraint fixtures with exact witnesses and input pins |
| C3 | Asynchronous checker integration | Snapshot binding, bounded jobs, cancellation/timeout, no-findings run manifests, stale-input and checker-version invalidation |
| C4 | Reachability adapters | Workflow-only hook counted reachable; scoped/unresolved indirect calls reported honestly; statement rules require body analysis |
| C5 | Predicate/policy obligation adapters | Implied preconditions and contradictory guards on a supported fragment; unsupported/satisfiability-unknown cases never marked proved |

Each semantic adapter ships its own supported-fragment fixtures and
counterexamples; C4/C5 are incomplete until real analysis exists. A
request returning `unknown` honestly handles unsupported input but does
not by itself implement that rule family.

End-to-end fixture: analyze an accepted caller/callee contract pair,
record a finding with exact versions, update the callee precondition
during another run, and verify the old result is only historical. Add
a workflow-only entry hook and an unresolved callback to distinguish
positive reachability evidence from unjustified dead-code claims.

## Open questions

Select the first compiler/solver adapter and its bounded expression
fragment during C3–C5 implementation. This RFC fixes reporting and
trust semantics without claiming that any one solver covers all rules.

## Rejected alternatives

- Let an LLM mark its own suggestions proved: loses the evidence boundary.
- Treat a graph path as executable feasibility: ignores guards and data.
- Treat no reported findings as success: hides missing/incomplete checks.
- Store only the latest result: destroys explanation and audit history
  when inputs or checker behavior change.
