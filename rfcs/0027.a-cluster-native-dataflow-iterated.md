It is a single, self-contained implementation-ready PRD with standard sections (Vision, Goals/Non-goals, Chosen Innovations, Cross-theme Integration, Acceptance Criteria mapped to the rubric, Implementation Phases, Open Questions).

Key resolutions:

- **Wall-clock vs. determinism:** wall-clock is confined to a liveness oracle that emits durable `BarrierTimeout` control records; operators and watermark arithmetic consume only log records. The invariant is reframed explicitly.
- **Operational parameters pinned:** defaults/bounds given for `max_records_per_barrier`, `max_barrier_idle_ms`, `global_complete_timeout`, `lease_duration`, `max_in_flight_repartition`, `repartition_partition_count`, chunk sizes, retention/GC windows.
- **Crate/tool grounding verified:** claims now point to real paths — `crates/nirdosha-ingestion-topic-kafka`, `crates/nirdosha-workflow/src/outbox.rs`, `crates/runtime-kernels/src/kernel/transact/durable.rs`, `crates/cargo-nirdosha/tests/guarantee_bundle.rs`, and the existing `cargo nirdosha check-certificate` command.
- **Snapshot determinism:** canonical binary serializer with sorted keys, fixed-width integers, length-prefixed blobs, normalized floats, enum discriminant+payload, and a Merkle `state_hash`; compaction safety rule specified.
- **Sink idempotency proof:** driver-verified `provider_capabilities.json` capability manifest plus runtime `SinkIntent` record and provider transaction; `at_least_once` remains possible.
- **HTTP ingress `event_id`:** new compile-time check on `HttpWebhook<T>` requiring `event_id: str`, with a v1 compatibility shim using a request fingerprint.
- **Control topic bootstrap:** `__nirdosha_control` created at deployment/provider auto-creation; initial epoch is 0; fleet bundle is a static signed sidecar, not a runtime topic.

Cross-theme tensions resolved:
- Full snapshots are made acceptable by async writes, 1 MiB chunking, and binary canonical format; delta snapshots deferred.
- Compile-time idempotency (theme C) is layered on top of provider transactions (theme A), not used alone.
- Static bundle (theme A) is mandatory at startup/join and paired with broker-level mTLS/ACLs and a best-effort runtime self-check.

Remaining ambiguity is collected in §9 as `OPEN QUESTION:` items (canonical serializer implementation detail, mTLS ops model, control-topic scaling, self-contained Raft mapping, ingress header convention, multi-input joins, self-check precision, provider capability manifest schema).
